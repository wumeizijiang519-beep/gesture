# 课程实验与结果记录协议

这是实验方案，不是已经采集的用户实验结果。算法完整和仿真脚本通过，不代表真人遥操作已达到某个成功率或帧率。

## 1. 最小验收顺序

首先运行自动化验收，保存 commit、Python 版本、pip freeze、模型哈希、JUnit 和三个仿真 episode。然后在目标笔记本执行 `doctor --camera 0`，生成自己的相机标定文件，并测量自己的掌宽。最后逐项执行真人检查并保存新的 episode：

| 现场检查 | 通过条件 | 必须记录 |
|---|---|---|
| 初始静止 | 未按 C、SPACE 时机械臂不跟手运动 | 录像/事件日志 |
| 三轴方向 | 分别上下、左右、前后移动，末端方向符合说明 | K、掌宽、视角 |
| 离合恢复 | 暂停、移动手、恢复时目标无突然跳变 | 重锚定前后位置 |
| 丢手 | 移出画面后停止；重新出现不自动恢复 | 超时、状态切换 |
| 双手 | 同时出现两手时停止/不接通 | 拒绝原因 |
| 锁定停止 | X 后 C/SPACE 不能解锁，R 后仍需重新接通 | 状态和事件 |
| 到达/路径 | 任务成功由 summary 定义判断，不靠口头宣称 | 成败、耗时、轨迹 |
| 抓放 | 看见方块实际抬起、释放并落到目标 | 状态轨迹与仿真录像 |

任何失败都保留，不用“调完参数后只留成功样本”替代完整实验记录。

## 2. 感知准确性实验

固定摄像头，锁定屏幕角度和分辨率。让同一只手在预先量好的多个距离位置保持近似同一掌姿。每个距离录制独立 episode，排除移动阶段后计算估计深度与人工参考距离差；参考应对应镜头光心附近到腕点的位置，注明人工测量和关节中心定位的不确定性。距离参考不是高精度动捕，报告时写“近似深度参考误差”，不要写毫米级真值。

对比：未标定 K vs 标定 K；默认掌宽 vs 实测掌宽。保持相机、同一人、照明、输入分辨率和版本不变。可再增加掌部倾斜、轻遮挡、弱光条件以分析失败范围。统计有效观测比例与所有试次，不能只保留系统返回 pose 的帧并称作整体准确率。

## 3. 稳定性与延迟

录制手掌保持静止的 20–30 s episode，再使用 `evaluate --static`，得到各轴手腕标准差。人的微动会被计入，结果是系统加操作者的观测抖动而非纯网络噪声。滤波前后机器人目标轨迹可在同输入重处理后比较。不要在大范围移动 episode 上调用 --static 并把标准差称为抖动。

推理耗时只覆盖模型调用；host_capture_to_control 是主机取帧完成到控制计算的年龄；两者都不是“手真实运动到屏幕反馈”的完整端到端延迟。完整延迟需要高速外部录像、可见同步事件等独立测量。记录 CPU、内存、线程数、相机帧率、目标 Hz 与实际运行耗时；配置 30 Hz 不等于测得 30 FPS。

## 4. 交互与任务实验

最小被试内比较可用 no-filter 与 One Euro 两条件，在到达、路径、抓放三任务上各做若干试次。给统一练习时间并平衡条件顺序，给每个操作者独立掌宽、固定共用 K。记录匿名参与者 ID、条件、顺序、训练次数、任务种子、成功/失败、wall 时间、active 时间、离合次数、停止次数、路径误差、主观易用性；未成功试次不计算为零耗时。

小组五人自测属于便利样本和课程探索，不能据此泛化到所有用户。分析可先报告每人配对差、均值/标准差和原始散点；样本量与分布不支持时不要硬套显著性结论。若分组测试，说明学习效应与顺序平衡。

## 5. 两类消融不得混淆

`python scripts/compare_filters.py --episode ... --output ...` 是**相同观测和事件序列的离线开环消融**。它控制输入差异，适合比较控制链的滤波影响。人没有看到另一条件的反馈并调整动作，所以它不等价于闭环真人实验，也不能从中推出“用户体验改善”。

使用 `live --filter none` 和 `live --filter one-euro` 分别开展真人试次则是闭环比较，但输入动作不同；需平衡学习/顺序并做多次重复。两类结果分别报告。

## 6. 汇报建议

中期展示：课程目标、与 EgoInfinity/MINT 的关系、坐标/尺度问题、已运行工程、自动化证据、摄像头初测失败案例。结题展示：保持相同主线，加入标定前后、滤波前后、三任务真人结果、失败边界和复现命令。不要将合成测试的准确数字当成实际摄像头三维误差，也不要将三条成功脚本称为统计可靠的 100% 遥操作成功率。
