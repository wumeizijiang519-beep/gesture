# 方法、坐标与数据契约

## 1. 课程要求与实现范围

选题 13 要求三部分：手部三维运动感知、手部运动到机械臂末端运动的映射及交互、仿真系统与典型任务验证（《课程设计选题_2026》第 18 页）。本项目分别由 geometry/vision、control、simulation/runtime 实现。相机标定、掌宽尺度、失败拒绝和回放是可验证工程所需，不将这些设计说成课程文件逐字规定。

## 2. 几何估计

记 MediaPipe 输出局部手形为 h_i、原始像素为 u_i。MediaPipe world landmarks 的原点是手部几何中心，不包含可直接用于遥操作的全局平移。先将它们转换成以腕点为原点的带尺度手形：

```text
s = measured_palm_width / ||h_5 - h_17||
H_i = s * (h_i - h_0)
(u_i, H_i, K, distortion) --SQPnP--> R_CH, t_CH
P_i^C = R_CH * H_i + t_CH
p_wrist^C = P_0^C
```

仅用 0、1、2、5、9、13、17 七个掌部点参与 PnP，避免远端手指弯曲对刚体姿态拟合的影响。手形每帧仍由网络估计，并非真实刚体，这一点是误差来源。正深度、合理距离、画面范围、掌部面积和重投影阈值筛掉不一致观测。阈值见代码；不是统计校准后的概率置信度。

已知 K 与掌宽是尺度先验。更大的指定掌宽会给出同比例更远的估计；测试对此有明确断言。K 不准确、遮挡、手掌转到近侧面、尺度个体差异都可能使深度偏移。低重投影误差仅表示投影自洽，并不证明三维位置真实准确。

掌坐标以 5−17 方向为 x，腕到中指 MCP 的正交分量为 y，叉乘为 z。所有旋转都在 SO(3) 中计算；四元数统一 xyzw；位置米、角度弧度、时间秒。

## 3. 手到机械臂映射

光学相机 +x 向右、+y 向下、+z 向前；机器人基座 +x 向前、+y 向左、+z 向上：

```text
R_BC = [[ 0,  0,  1],
        [-1,  0,  0],
        [ 0, -1,  0]]
p_goal^B(t) = p_anchor^B + gain * R_BC * (p_hand^C(t) - p_hand_anchor^C)
```

这是**交互轴约定**，不是由外参标定恢复的真实相机—机器人刚性安装变换。机器人在独立虚拟世界中；不声称与用户桌面的物体完成现实空间注册。

SPACE 接通时，同时保存当前手位姿和当前真实仿真末端位姿作为锚点。松开可让人调整姿势；再次接通重锚定，不传播离合间的手移动。C 仅允许中立接受，不估计 K。

One Euro 滤波先于映射；目标进入工作空间裁剪、末端目标速度/加速度整形。`--orientation` 使用相对掌旋转、坐标变换、最大 60 度相对旋转与角速度约束。夹爪依据 thumb4-index8 距离/掌宽连续控制，宽度上限 0.08 m。

目标运动约束不等于机器人真实运动的严格证明：物理电机、碰撞、急停、工作空间边界和 overshoot clamp 可优先于平滑加速度。当前碰撞检查验证 IK 末端候选姿态，不是全路径连续碰撞认证；因此本代码仅用于仿真。

## 4. 时间与状态机

`DISARMED -> C + SPACE -> ACTIVE`。失手、过期或跳变进入 LOST，恢复后仍需 SPACE。X 进入 ESTOP，只有 R 清除，随后 C+SPACE 才能再次启动。多手出现直接拒绝，减少身份切换。

采集、推理独立线程，各只有一个 latest-value slot。新输入替换旧输入而非排无限队列。控制循环独立执行，以最后有效观测时间触发超时。摄像头时间为主机 read 完成时刻，相对统一 monotonic 起点；不是传感器曝光时间。GUI 绘制和日志写入仍在控制循环中，CPU 负载会使实际循环低于目标 30 Hz；这不是硬实时系统。

仿真始终使用 240 Hz 固定物理步，控制频率必须整除 240。sim_time 表示模拟步数对应时间，active_time 仅累计接通控制时的模拟时间，control_time 为输入时间轴/主机时钟；不能相互代用。用户研究同时记录 wall_runtime_s 与 active_seconds。

## 5. 物理与任务

Franka 模型来自固定 PyBullet 版本附带的 pybullet_data；控制臂七关节与两夹爪滑动关节。另一个 DIRECT 客户端用于候选 IK/FK 和末端候选碰撞检查，不污染真实仿真状态。正式仿真只施加关节电机目标，方块依靠接触、摩擦、重力运动；没有抓取时的固定约束或物体瞬移。`restore_visual_state` 只用于 `replay --mode state` 展示。

到达成功：末端进入半径 0.025 m 球并保持 0.5 s。路径任务先 3 s 到起点，接着 16 s 绕一圈，轨迹 RMSE 小于 0.035 m 后保持判据。抓放成功：方块曾被抬到 z>0.1 m，随后落在目标区域（XY 半径 0.055 m、合理台面高度），夹爪打开且末端离开，保持 0.5 s。参数是本项目任务定义，不是来自参考论文的标准。

## 6. Episode 数据

每个 episode 是新目录。meta 记录 schema、代码提交、Python/依赖版本、模型 SHA256、内参、掌宽、种子、任务/控制配置与输入类型。steps 每行记录：输入帧编号及时间、原始关键点、三维估计及拒绝原因、事件、动作、执行后机器人状态、施加电机目标。summary 汇总成功条件和失败原因；manifest 校验字节完整性。

重要时序：第 k 行 observation 是该步控制使用的最近观测，command 是随后施加的动作，robot 是执行该步后的状态。因此做学习数据时不能无说明地将同一行 robot 当作动作前状态；动作前机器人状态可从前一行取得，首帧需单独处理。本项目没有实现行为克隆或 VLA 训练，也不将 NPZ 称为现成 LeRobot 数据集。

`replay --mode command` 重新执行动作并比较轨迹；state 模式只呈现原状态。`reprocess` 固定原始关键点与原始交互事件时间、只更换滤波，不重新运行检测器；不同方法触发不同停止会导致后续轨迹不同，这也是结果，不能删除。

RGB 默认不存储。开启后 AVI 只保存新输入帧，JSONL 指向 video_frame_index；实际输入丢帧/变速时需要 JSONL 对齐。固定帧率离线 video 模式与任意录制 AVI 的真实时间语义不等同；高保真再分析优先用原始 episode。
